# Cloud Functions

This directory contains the WeChat CloudBase functions used by the mini program. Each function is deployed independently from WeChat DevTools and has its own `package.json`.

## Runtime

- Runtime: Node.js on WeChat CloudBase.
- Shared dependency: `wx-server-sdk`.
- Authentication: functions use `cloud.getWXContext().OPENID` to identify the current WeChat user.
- Data access: most business writes happen in cloud functions so the frontend does not need broad database write permissions.

## Required Collections

Create these collections before testing the app with a real cloud environment:

| Collection | Main Fields | Notes |
| --- | --- | --- |
| `users` | `openid`, `uid`, `nickname`, `avatarUrl`, `coupleId`, `createdAt`, `updatedAt` | Created or returned by `login`. |
| `couples` | `memberIds`, `createdBy`, `status`, `deleteAt`, `createdAt`, `updatedAt` | Represents one shared couple space; dissolved spaces are retained for 30 days. |
| `invites` | `inviteCode`, `creatorUserId`, `coupleId`, `status`, `expiresAt`, `createdAt`, `acceptedAt` | Used by invite creation and acceptance. |
| `categories` | `coupleId`, `name`, `sort`, `createdAt`, `updatedAt` | Shared menu categories. |
| `dishes` | `coupleId`, `categoryId`, `name`, `price`, `status`, `tasteOptions`, `isDeleted`, `salesCount` | Shared dishes. Deleted dishes are soft-deleted. |
| `orders` | `coupleId`, `guestUserId`, `chefUserId`, `items`, `status`, `remark`, `createdAt`, `updatedAt` | Tracks order lifecycle. |
| `reviews` | `orderId`, `coupleId`, `rating`, `content`, `createdAt` | Attached after completed orders. |
| `monthlyReports` | `coupleId`, `month`, `summary`, `stats`, `createdAt` | Snapshots generated by `monthlyReport`. |

Indexes are not strictly required for the local prototype, but production use should add indexes for frequent filters:

- `users.openid`
- `invites.inviteCode`
- `categories.coupleId + sort`
- `dishes.coupleId + isDeleted + status`
- `orders.coupleId + status`
- `reviews.coupleId`
- `monthlyReports.coupleId + month`

## Function Reference

| Function | Responsibility |
| --- | --- |
| `login` | Initializes or returns the current user by `OPENID`. |
| `saveProfile` | Updates nickname and profile fields for the current user. |
| `getCoupleData` | Returns current couple space and partner details. |
| `dissolveCouple` | Marks a couple space for deletion, detaches both users, and starts the 30-day order retention window. |
| `createInvite` | Creates an active invite code for the current user. |
| `getInviteData` | Loads invite details and creator information by invite code. |
| `acceptInvite` | Accepts an invite, binds both users into a couple space, and ensures default menu data exists. |
| `resetDefaultMenu` | Rebuilds the current couple space menu from default categories and dishes. |
| `getMenuData` | Lists categories, lists dishes, or returns one dish after access validation. |
| `manageDish` | Creates/updates dishes, creates categories, updates dish status, and soft-deletes dishes. |
| `createOrder` | Creates an order from the current user's cart and assigns the partner as chef when available. |
| `getOrderData` | Returns active orders, historical orders, and stats for guest or chef views. |
| `acceptOrder` | Moves an order from pending to accepted. |
| `completeOrder` | Marks an accepted order as completed and increments dish sales counts. |
| `cancelOrder` | Cancels an order in the same couple space. |
| `submitReview` | Adds a review for a completed order and marks it reviewed. |
| `monthlyReport` | Generates a monthly report and can optionally send a subscribe message. |
| `clearOrders` | Removes orders and reviews for the current couple space; locked unless `ALLOW_ORDER_RESET=true` is explicitly configured for development. |
| `purgeExpiredCouples` | Daily timer that removes orders and reviews from couple spaces whose 30-day retention window has expired. |

## Deployment

Deploy from WeChat DevTools:

1. Import the repository root as the project.
2. Confirm `project.config.json` points to `miniprogram/` and `cloudfunctions/`.
3. Confirm `miniprogram/app.js` uses your cloud environment ID.
4. Right-click each function directory.
5. Choose `Upload and deploy: cloud install dependencies`.

Recommended deployment order:

```text
login
getCoupleData
dissolveCouple
createInvite
getInviteData
acceptInvite
resetDefaultMenu
getMenuData
manageDish
createOrder
getOrderData
acceptOrder
completeOrder
cancelOrder
submitReview
monthlyReport
clearOrders
purgeExpiredCouples
saveProfile
```

The order is not a hard dependency graph, but deploying login and read functions first makes smoke testing easier.

## Local Testing

Most cloud-function behavior is covered by Node.js tests in `tests/`. These tests use local stubs and do not require a live WeChat cloud environment:

```bash
npm test
```

Before deploying behavior changes:

1. Run `npm test`.
2. Deploy the changed function.
3. In WeChat DevTools, invoke the user flow that calls it.
4. Check the cloud function logs for business errors and permission failures.

## Security Notes

- Never hard-code cloud secret keys, third-party API keys, cookies, or database credentials in cloud functions.
- `OPENID` must come from `cloud.getWXContext()`, not from frontend parameters.
- Any mutation by `orderId`, `dishId`, `categoryId`, or `inviteCode` must verify the current user belongs to the target `coupleId`.
- Frontend input is treated as untrusted. Cloud functions should validate ownership and status transitions.
- Subscribe message template IDs are identifiers, not secrets, but they are app-specific and should be replaced for another mini program.
