# 菜品大全图标语义匹配设计

## 目标

优化菜品大全卡片中的封面图标，使图标尽量贴近菜名或食材，同时保持菜谱同步后仍然有效。范围仅包含菜品大全卡片及从菜品大全加入菜单时生成的默认 emoji，不修改添加/编辑菜品页面的图标选择器。

## 设计

在 `miniprogram/utils/recipe-library.js` 增加纯函数 `getRecipeCover(recipe)`，统一负责菜谱图标选择。规则按以下顺序执行：

1. 菜名关键词匹配。
2. 食材关键词匹配。
3. 菜谱分类兜底。
4. 原始 `recipe.cover` 兜底，最后返回稳定的 `🍽️`。

关键词规则按具体程度排序，避免复合菜名误判。例如“鱼香肉丝”不能因包含“鱼”而被当作海鲜，应优先命中“肉丝/猪肉”等肉类规则；“可乐鸡翅”命中鸡肉图标；菜名未命中但食材包含虾仁时命中虾类图标。

`recipeToDishPayload` 改为调用 `getRecipeCover`，保证菜品大全卡片和一键加入菜单后的菜品使用同一套图标规则。原始离线生成文件 `miniprogram/data/howtocook-recipes.js` 不直接修改，避免下次同步覆盖手工调整。

## 测试

在现有 `tests/recipe-library.test.js` 中补充行为测试，覆盖菜名优先、复合菜名防误判、食材匹配、分类兜底、加入菜单图标一致性，以及缺少字段时的默认图标。现有菜谱筛选、分页、加入菜单和图标选择器测试保持通过。

## 边界

- 规则匹配大小写不影响中文关键词判断。
- 规则只读取菜谱对象，不修改输入数据。
- 未命中规则的菜谱仍可使用数据源原有 `cover`，保证兼容已有数据。
- 本次不新增网络图片资源或第三方依赖。
