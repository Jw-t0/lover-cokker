# 首页推荐菜随机展示设计

## 目标

首页推荐菜不再固定展示菜品列表的前 3 项，而是从当前可用的完整菜品列表中随机抽取最多 3 项。用户重新进入或刷新首页时，有机会看到不同推荐菜。

## 方案

在小程序端增加一个纯函数 `pickRandomDishes(dishes, count, random)`：

- 输入数组不会被修改；
- 默认最多返回 3 项；
- 菜品不足 3 项时返回全部菜品；
- 使用 Fisher-Yates 洗牌，随机源通过可选参数注入，便于测试；
- 单人体验的本地默认菜单和已绑定用户的云端菜单统一走这个函数。

不改云函数和数据库查询。随机逻辑放在前端可以避免新增接口，也不会影响菜单排序、下单数据或菜单管理。

## 数据流

`loadHome()` 获取菜品列表后，调用 `pickRandomDishes()`，再将结果写入 `recommendedDishes`。现有首页推荐卡片和点击进入点菜流程保持不变。

## 测试

- 验证抽样数量不超过 3；
- 验证输入数组保持不变；
- 使用确定性随机源验证抽样结果；
- 验证首页从完整列表调用随机抽样，而不是固定 `slice(0, 3)`。
